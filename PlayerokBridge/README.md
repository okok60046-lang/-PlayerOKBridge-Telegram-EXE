# PlayerOK Bridge (C#)

Перенос Telegram↔PlayerOK бота на C# + Avalonia (окно) без Python.

## Сборка

Нужен .NET 8 SDK. В папке проекта:

```
dotnet restore
dotnet build -c Release
```

Один `.exe` для Windows:

```
dotnet publish -c Release -r win-x64 --self-contained -p:PublishSingleFile=true
```

Файл появится в `bin\Release\net8.0\win-x64\publish\`.

## Первый запуск

1. Откройте вкладку «Настройки», введите токен Telegram-бота, свой Telegram ID, токен PlayerOK. Нажмите «Сохранить».
2. Нажмите «Запустить» на вкладке «Работа».
3. В Telegram отправьте боту `/start`.

Данные хранятся в `%AppData%\PlayerokBridge\`. Чтобы перенести старые ответы, скопируйте туда
`product_replies.json`, `auto_replies.json`, `notify_settings.json` из `data-sample\` (формат совместим с Python-версией).

## Команды в Telegram

`/balance`, `/stats`, `/deals`, `/check <название лота>`; Reply на уведомление отправляет текст покупателю.

## Не перенесено из Python-версии (пока)

Чаты и фильтры в Telegram, пресеты, избранное и поиск по товарам.

## Если PlayerOK возвращает проверку на бота

playerokapi использует TLS-отпечаток Chrome (curl_cffi), у .NET HttpClient он другой. Обновите cookie `__ddg*` и User-Agent из браузера;
если не помогает, нужен транспорт на curl-impersonate (заменяется в `Playerok/GraphQlTransport.cs`).


## Изменение: кнопка «Запустить» запускает Python-бота

Теперь кнопка запускает `bot.py`, который должен лежать рядом с EXE. Настройки из вкладки «Настройки» передаются процессу через переменные окружения; секреты не записываются в командную строку. Для запуска Python 3 должен быть установлен и доступен как `python` или `py`.

Перед первым запуском установите зависимости в командной строке Windows:

```powershell
python -m pip install -r requirements-bot.txt
```

Сборка EXE по-прежнему требует .NET 8 SDK:

```powershell
dotnet publish -c Release -r win-x64 --self-contained -p:PublishSingleFile=true
```

Положите `bot.py` рядом с опубликованным EXE.

## Изменение: журнал, трей и напоминание о невыданных заказах

- **Журнал с фильтрами.** На «Обзоре» и в отдельном окне («↗ В отдельном окне» или пункт «Журнал событий» в меню значка в трее): фильтр по уровню (все / предупреждения и ошибки / только ошибки), по теме (подключение, опрос чатов, покупки, Telegram, Python-бот), поиск по тексту, «Следить за новыми», очистка и копирование. Ошибки красные, предупреждения жёлтые. Ошибки загрузки чатов и продаж для фильтров теперь тоже попадают в журнал.
- **Трей.** Закрытие и сворачивание окна прячут его в трей, как и раньше. Теперь при новой покупке или невыданном заказе значок мигает красной точкой, пока окно скрыто или не в фокусе. Мигание прекращается, когда вы открываете окно. В подсказке значка видно число новых событий.
- **Напоминание о зависшей сделке.** Если заказ оплачен, но не выдан дольше N минут (по умолчанию 15), приложение показывает уведомление Windows, играет звук, мигает значком и пишет в журнал. Повтор по той же сделке каждые 30 минут (настраивается). Настройки: вкладка «Уведомления» → «Зависшие сделки». Работает, пока приложение подключено к PlayerOK. Сделки со спором и старше 3 суток не напоминаются. Telegram-уведомления о зависших сделках не отправляются: Telegram обслуживает Python-бот.

## Изменение: работа с чатами

- В переписке показывается вся история чата (все страницы), без служебных сообщений в `{…}`; длинная история отправляется несколькими сообщениями Telegram, кнопки — под последним.
- Сообщения помечены: ➡️ Вы / ⬅️ покупатель / 🔰 поддержка, добавлены время и разделители по дням.
- В списке чатов превью и фильтры по-прежнему используют расшифровку последнего события (например «Поддержка сделала возврат средств»), иначе фильтры перестали бы работать.

## Изменение: ответы по товарам в окне чатов

- Быстрые ответы убраны. Вместо них под заголовком чата — список ответов по товарам, каждый пункт назван ключевыми словами (через « · »).
- Клик по пункту вставляет готовый текст в поле сообщения ({buyer}, {seller}, {item}, {price}, {deal_id} подставляются автоматически). Текст можно поправить и нажать «Отправить».
- Пункты, подходящие под купленный в этом чате товар, идут первыми и отмечены ✓.
- Служебные сообщения `{{...}}` скрыты из переписки; в списке диалогов вместо них показывается читаемый текст.

## Изменение: компоновка и скорость отправки

- Список ответов по товарам уменьшен и стоит над перепиской. Кнопка «Отправить» убрана: Enter отправляет, Shift+Enter — новая строка. Поле ввода опущено в самый низ.
- Сообщение появляется в чате сразу, отправка идёт в фоне; история больше не перезагружается после каждой отправки. При ошибке текст возвращается в поле.
- Запись (отправка) идёт по отдельной очереди и не ждёт загрузки истории; отметка «прочитано» выполняется в фоне.

- Ответы по товарам: кнопка «🎯 Ответы по товарам ▾» слева над перепиской открывает вертикальную таблицу с ключевыми словами; клик по строке вставляет текст в поле и закрывает таблицу.
- Enter в поле ввода обрабатывается раньше самого TextBox (tunnel-обработчик), поэтому отправка по Enter теперь срабатывает.

## Изменение: загрузка чатов, скорость, автообновление, автоответ в приложении

- **Ошибка «When paging backwards, a 'before' argument is required!»** — исправлена. Раньше история запрашивалась как `last` без `before`, сервер PlayerOK такое отклоняет. Теперь `first: 24` (самые свежие) и далее `after: <курсор>` (предыдущие).
- **История по 24 сообщения.** При открытии чата грузятся последние 24. Когда прокрутите вверх до конца, подгружаются предыдущие 24 — уже показанные нижние сообщения не удаляются и не перерисовываются, позиция прокрутки сохраняется.
- **Быстрое переключение между чатами.** Раньше при каждом открытии чата заново скачивались ВСЕ продажи (это и давало ~15 секунд). Теперь покупка определяется по сообщениям чата, продажи грузятся один раз в фоне, открытые чаты кэшируются (повторное открытие мгновенное, новые сообщения подтягиваются фоном), устаревшие запросы отменяются.
- **Автообновление чатов.** Фоновый монитор опрашивает PlayerOK каждые ~3 секунды: список чатов и открытый чат обновляются сами. Непрочитанные чаты помечены красной меткой со счётчиком (в списке и на пункте меню «Чаты»), число непрочитанных показано в заголовке окна. Новая покупка — «🛒 Новая покупка!» и красный «!» в строке чата.
- **Автоответ в приложении.** Когда монитор видит новую оплаченную сделку, он подбирает ответ по ключевым словам (вкладка «Ответы по товарам», та же логика, что в Telegram-боте) и отправляет его покупателю. Покупки, оплаченные пока приложение было закрыто, догоняются при запуске (за последние 24 часа; если вы уже писали в чат — не дублируется). Обработанные сделки запоминаются в `autoreplied_deals.json`.
- Автоответ в приложении работает, только когда Python-бот НЕ запущен (иначе покупатель получил бы два сообщения). Включается/выключается галочкой на вкладке «Ответы по товарам».
- Если токен PlayerOK сохранён, приложение подключается само при запуске. Кнопка «Остановить» отключает автообновление и автоответ.
- Защита от пропуска покупок: повторные попытки получить данные сделки; если не получилось — данные берутся из самого сообщения; новые чаты проверяются за последние 15 минут. Исправлено повторное воспроизведение старых событий при новом сообщении в известном чате.

## Изменение: AFK-режим

- Во вкладке «🤖 Автоответы» рядом с ответами по товарам находится блок «AFK-режим». Если он включён, после автоответа по товару покупатель получает второе сообщение — AFK.
  Порядок всегда такой: 1) ответ по товару → 2) пауза (0–30 с, по умолчанию 2 с) → 3) AFK-сообщение. Один раз на сделку.
- Подстановки в тексте: `{buyer}` — ник покупателя, `{seller}` — ваш ник, `{item}` — название товара, `{price}` — цена, `{deal_id}` — номер сделки.
  Пример: `Здравствуйте, {buyer}!`. Кнопка «Предпросмотр» показывает готовый текст.
- «Отправлять AFK, даже если ответ по товару не подобран» — покупатель узнает, что вас нет на месте, и когда ключевое слово не сработало.
- Настройки лежат в `%AppData%\PlayerokBridge\afk_settings.json`. Работает и в приложении, и в Python-боте (`bot.py` перечитывает файл при каждой сделке —
  включать/выключать AFK можно без перезапуска бота). Галочка включения сохраняется сразу.

## Стабильность чатов и уведомления Windows

- История чата загружается страницами по 24 сообщения; дозагрузка старых страниц сохраняется.
- При обновлении последней страницы контрольный ключ меняется только после успешного ответа PlayerOK. Временная сетевая ошибка не должна «съесть» обновление.
- Монитор не сдвигает ID последнего сообщения до успешного получения и обработки истории. Ошибочные сообщения остаются на повторную проверку.
- Повторный курсор пагинации останавливает дозагрузку, чтобы не зациклить запросы.
- В «Уведомлениях» находятся переключатель системных уведомлений Windows и кнопка тестового уведомления. Уведомления отправляются о новых входящих сообщениях и новых сделках.
- Уведомления Windows используют системную область уведомлений (Shell_NotifyIcon); фактический вид всплывающего уведомления зависит от версии Windows и её настроек уведомлений.

## Обновление интерфейса: товары, баланс и навигация

- Навигация перенесена в постоянно видимую левую панель. Карточка баланса PlayerOK закреплена вверху: показывает общий баланс, доступную и замороженную суммы; кнопка `↻` обновляет данные.
- Обычное переключение вкладок теперь мгновенное: снимки страниц и анимационный overlay больше не запускаются при каждом клике. Предпросмотр эффектов в разделе GUI оставлен отдельно.
- Тест системного уведомления Windows перемещён в «Уведомления».
- AFK-режим и просьба об отзыве находятся в «Автоответах» рядом с ответами по товарам.
- Вместо отдельной вкладки отзывов добавлена «Мои товары»: список объявлений, фильтр по игре (по фактическим играм ваших объявлений), поиск, покупки, оборот продаж, просмотры и состояние публикации. Вкладка не привязана только к PUBG Mobile.
- Статистика покупок и оборота использует даты и статусы сделок PlayerOK; оборот — сумма цен сделок, не чистая выплата после комиссии. День считается с полуночи, неделя — с понедельника, месяц — с первого числа. Просмотры «за всё время» берутся из счётчика PlayerOK; прирост за текущий день/неделю/месяц собирается локально с момента начала наблюдения приложением. До накопления двух снимков за период отображается `—`; исторические просмотры до первого снимка восстановить нельзя. Файл истории: `%AppData%\PlayerokBridge\listing_views_history.json`.
- Для черновиков и истёкших/отклонённых объявлений доступна публикация, для активных — поднятие. Перед платным действием показывается тариф и стоимость, операция запускается только после подтверждения.
- Кнопка «Создать товар» открывает встроенный мастер: игра ищется в каталоге PlayerOK, затем загружаются категории, способы передачи, характеристики и поля продавца. Эти данные не зашиты отдельно для PUBG Mobile — мастер использует схему выбранной игры/категории. Можно добавить до 10 фотографий. После заполнения создаётся черновик через GraphQL PlayerOK; затем приложение показывает варианты публикации и стоимость, а публикация запускается только после выбора тарифа.

## Исправления (ревизия кода)

**bot.py**
- Уведомления больше не теряются: длинный текст (> 4000 символов) режется без разрыва HTML-тегов, при flood-лимите и сбое сети — повторные попытки, при ошибке разбора HTML — отправка обычным текстом, ошибки пишутся в лог.
- Кнопка «📨 Отправить ответ» под уведомлением о покупке теперь действительно появляется (название лота раньше не передавалось в `notify`), а текст уходит с подставленными `{buyer}`, `{seller}`, `{item}` — раньше покупателю мог уйти буквальный шаблон.
- Слушатель PlayerOK: если `listen()` завершился без ошибки, цикл ждёт 15 с, а не молотит API без паузы.
- `main()`: сбой приветственного сообщения больше не роняет бота; сессия Telegram закрывается при выходе.
- Наборы «уже отвечено» (автоответ, AFK, просьба об отзыве) ограничены по размеру — память не растёт бесконечно.
- Чаты запрашиваются по 24 за запрос вместо 10; история чата читается не более `CHAT_HISTORY_MAX_PAGES` страниц (по умолчанию 10 × 24 сообщения, переменная окружения).
- Сделки: замок против одновременной двойной загрузки; даты разбираются один раз (сортировка и статистика).

**C#**
- `ReplyRenderer`: пустой ник покупателя больше не оставляет в сообщении буквальный `{buyer}` (запасное «покупатель», как в bot.py).
- `TelegramApi`: безопасная обрезка HTML, запасная отправка обычным текстом, повтор при HTTP 429, понятная ошибка вместо JsonException, если ответ не JSON.
- `GraphQlTransport`: проверка «страницы защиты от ботов» только для не-JSON ответов (раньше сообщение с фразой вроде «Checking your browser…» давало ложную тревогу и сканировало каждый ответ); повтор при 429/502/503/504.
- `JsonStore.Save`: общий замок — одновременные записи больше не падают с «файл занят».
- `ListingStatsStore`: файл истории пишется только при появлении новых точек.
- `AppHost`: обработчик `Exited` не обращается к полю `_pythonBot` (NRE / не тот процесс); `HttpClient` для картинок создаётся под замком и освобождается.


## Вход, язык и шрифт

- При первом запуске открывается окно авторизации: сначала выбор языка (RU / EN), затем ввод токена Playerok
  (cookie `token`). Токен проверяется запросом к Playerok. Если проверка не прошла (например, сеть), можно
  сохранить токен без проверки.
- Если язык не выбран или токена нет, окно показывается снова. Если токен уже был сохранён в старой версии,
  попросят только выбрать язык.
- **Настройки → «Внешний вид и язык»**: язык (русский / English) и шрифт интерфейса меняются сразу, без
  перезапуска, и сохраняются в `app_settings.json` (`language`, `ui_font`).
- Переводы лежат в `Core/Loc.cs` (словарь `En` и список `Prefixes`). Чтобы перевести новую строку, добавьте
  пару «русский → английский»: интерфейс подставит её сам. Для строк, которые собираются в коде,
  используйте `Loc.T("по-русски", "in English")`.
